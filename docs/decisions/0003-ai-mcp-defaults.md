# ADR 0003：内置 AI 和 MCP 第一版的默认值

- 状态：已采纳
- 日期：2026-11-24
- 依据：`crates/aster-shell/README.md` 的“AI 助手与 MCP”一节；技术方案“内置 AI 助手与 MCP”一章末尾的待定事项

## 背景

技术方案“内置 AI 助手与 MCP”一章的设计照用户的 MySSH 项目来：MCP 服务跑在桌面程序里，`aster-mcp-bridge` 只把 stdio 转到本机套接字；内置助手和外部 MCP 客户端共用一套工具目录、权限、审批和审计日志。工具层的四项决定已在 2026-11-22 定下：

- 权限按文件夹规则加单个文档的会话授权，默认关闭。
- 读文档也要授权。
- 只有“完全”级别可以自动保存。
- 外部客户端的审批用不抢焦点的卡片。

这一章末尾还有十项待定事项。第一版实现（main 的 `bb473e3`）先按默认值做了其中几项，并在 README 里列出，等用户确认。

## 决定

2026-11-24 用户同意了以下默认值：

1. **MCP 只走本机套接字，不开 HTTP 端口。** 对应待定事项里的“回环 HTTP”：第一版不做。外部客户端通过 `aster-mcp-bridge` 接入，套接字只允许同一个系统账户连接。
2. **对话只存在内存里，不写盘。** 对应待定事项里的“对话历史的存储”：关掉程序，对话就没了。
3. **新文档默认对 AI 不可见；给当前文档设的权限只在这次运行里有效。** 持久的权限只来自文件夹规则。
4. **发送前遮盖密钥默认开着。** 它也可能遮掉文档里看起来像密码的文字，用户可以在设置里关掉。

另外，Claude 的默认模型是 `claude-opus-5-5`；OpenAI 和 DeepSeek 没有写死模型，由用户自己填写。

## 仍然待定

方案那一章末尾的其余几项，这次没有决定：

- 托盘常驻。
- AI 放在哪个阶段。
- 是否需要 Phase 0 验证。
- 采用哪个 MCP SDK。
- 许可证允许清单的调整。
- 没有 Secret Service 的 Linux 怎么存 API Key。
- 是否提供不带 AI 的构建。
- 是否让 Aster 作为 MCP 客户端去连外部服务。

## 后果

- 想让外部程序通过 HTTP 连接，或者想保留对话记录，都要另做决定，并加一份新的 ADR。
- 第一版的权限持久化只有文件夹规则，所以给单个文档的授权，每次启动都要重新给。
- 2026-11-24 的安全审查列出的问题（审批卡片的内容、图片路径、Key 和接口地址的绑定、限额、审计日志）在后续修复，和这几项默认值无关。
