# G1：自绘表面内的输入法

Phase 0 的第一道关卡。要回答的问题只有一个：在 Slint 窗口里，一块由我们自己排版、自己渲染的文档区域，能不能正常接收中文和日文输入法的组字、选词和上屏。

Slint 1.19 没有向自定义控件开放输入法接口，所以这里绕过 Slint，经它的 `unstable-winit-030` 窗口事件钩子直接从 winit 取输入法事件，并自己告诉 winit 候选窗该放在哪里。

## 运行

```sh
cargo run -p g1-ime
```

窗口里的白色页面不是 Slint 控件。文字由 Parley 排版、vello_cpu 渲染，再作为一张图交给 Slint 显示。表面层的代码已经搬到 `crates/aster-surface`，应用外壳 `crates/aster-shell` 用的是同一份；这个工程只剩窗口和日志。每个输入法事件都会打印到 stderr，并汇总在窗口顶部和底部。

其他入口：

```sh
cargo test -p aster-surface                       # 表面层的单元测试，不开窗口
cargo run -p g1-ime -- --dump out.png             # 不开窗口渲染一帧
cargo run -p g1-ime --example fallback_probe      # 打印汉字实际回退到哪款系统字体
spikes/bundle-macos.sh g1-ime                     # macOS：打成最小 .app 包
```

## 测试清单

点一下白色页面，切到中文或日文输入法，逐项操作。每一项都同时看窗口和 stderr 日志。

1. 输入拼音或罗马字：预编辑串出现在光标处并带下划线，日志里是连续的 `Preedit`。
2. 候选窗出现在预编辑串所在行的下方，不遮挡正在输入的文字。
3. 选词上屏：文字只出现一次，日志里是一条 `Commit`。
4. 组字过程中按 Esc：预编辑串消失，不留下任何字符。
5. 把光标点到已有文字的中间再组字：文字插在光标处，候选窗跟到那一行。
6. 组字过程中切到别的窗口再切回来：不残留预编辑串，可以继续输入。
7. 在中文、日文、英文输入法之间来回切换后继续输入。
8. 把窗口拖到另一台缩放比例不同的显示器上，重复第 1 到 3 项。

请把 stderr 日志和有问题的截图一起回传，并注明系统版本、桌面环境和输入法框架。

## 结果

| 平台 | 输入法 | 结果 |
| --- | --- | --- |
| macOS 27.0.1，Apple Silicon | 简体拼音 | 第 1 到 5 项通过 |
| macOS 27.0.1，Apple Silicon | 日文罗马字 | 第 1 到 3 项通过 |
| Windows 11 | 微软拼音、微软日文 | 未测 |
| Linux X11 | ibus | 未测 |
| Linux Wayland | fcitx5 | 未测 |

macOS 上的第 6 到 8 项还没有测。

## 实测中发现的问题

- **汉字回退字体只缓存一份**。fontique 把“汉字、默认语言”的回退结果缓存成一份，谁先查询谁决定。在系统语言是日文的 Mac 上先缓存的是 Hiragino Sans，它没有简体专用字的字形，于是“输、这、图、进”等字显示成方块。苹方字体在当前 macOS 上也读不出来。Slint 自己的界面文字用的是同一套库，有同样的问题。这里的处理是显式设置回退链，见 `crates/aster-surface` 里 `text_surface.rs` 的 `HAN_FALLBACK_FAMILIES` 和 `host.rs` 的 `configure_shell_fonts`。
- **必须打开 Parley 的 `complex-scripts` 特性**。不打开时每次排版中日文都会向 stderr 打印 ICU 分词错误。
- **切换输入法时 winit 会发一次 `Disabled`**，下一次组字开始时再发 `Enabled`。收到 `Disabled` 必须清掉预编辑串。
- **日文候选窗打开时按回车**，第一次只关闭候选窗，第二次才上屏。还没有和系统原生应用逐键对比，不确定这是否就是系统行为。
- **候选窗的水平位置**比预编辑串起点偏左约两个字宽。这是 Parley 的 `ime_cursor_area` 故意把区域向两侧外扩造成的，需要贴齐时改用光标矩形。

## 自动化测试的限制

向后台窗口注入的按键不经过系统输入法，只会被当成普通按键。输入法测试必须让窗口处于前台并发送真实按键。用脚本切换输入法后，还需要切一次焦点，新的输入法才真正生效。
