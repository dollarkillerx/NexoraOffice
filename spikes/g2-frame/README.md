# G2：帧路径

Phase 0 的第二道关卡。要回答的问题：文档由我们自己在 CPU 上排版和渲染、每帧把一整张图交给 Slint 显示，这条路径在滚动和打字时够不够快。

测试内容是一篇 3000 段的中文、日文、英文混排文档，每段有自己缓存的排版结果，编辑只重排被改动的那一段。实现了两种出帧策略用来对比：

- **整屏重绘**：每帧把整个视口重新渲染，直接画进交给 Slint 的像素缓冲。
- **瓦片缓存**：把文档切成 256 像素高的横条，各渲染一次后缓存，每帧只把可见的行拷进输出缓冲。

## 运行

务必使用 release 构建，debug 构建的数字没有参考价值。

```sh
cargo run --release -p g2-frame -- bench                  # 无窗口基准，默认 2560×1440
cargo run --release -p g2-frame -- bench 3840 2160        # 指定分辨率
cargo run --release -p g2-frame -- window tiled           # 窗口内测量，瓦片缓存
cargo run --release -p g2-frame -- window full 0          # 窗口内测量，整屏重绘，单线程渲染
cargo test -p g2-frame
```

窗口内测量是全自动的：先滚动 600 帧，再模拟 200 次按键，打印结果后退出。窗口必须在前台且不被遮挡。macOS 上从命令行直接启动的窗口可能不在前台，可以先打包再启动：

```sh
open -n -W "$(spikes/bundle-macos.sh g2-frame release)" --args window tiled
```

## 结果

测试机：Apple M6，12 核，32 GB，macOS 27.0.1，内置屏 60 Hz。2026-11-22。

### 无窗口：出一帧的耗时（毫秒，p95）

| 场景 | 2560×1440 | 3840×2160 |
| --- | --- | --- |
| 滚动，整屏重绘，单线程 | 6.04 | 11.79 |
| 滚动，整屏重绘，9 线程 | 2.79 | 5.20 |
| 滚动，瓦片缓存，单线程 | 2.52 | 4.53 |
| 滚动，瓦片缓存，9 线程 | 2.06 | 3.89 |
| 快速滚动（每帧 600 px），瓦片缓存，单线程 | 4.52 | 7.10 |
| 打字，整屏重绘，单线程 | 6.01 | 12.80 |
| 打字，瓦片缓存，单线程 | 4.03 | 6.49 |
| 打字，瓦片缓存，9 线程 | 3.38 | 5.26 |

全文排版 3000 段用时约 0.36 秒，单段重排的 p95 约 0.5 ms。

### 窗口内：2560×1440，Slint 1.19 加 Skia 渲染器

| 配置 | 迟到的帧 | 出帧 p95 | Slint 绘制 p95 | 按键处理加绘制 p95 | 按键赶上下一次刷新 |
| --- | --- | --- | --- | --- | --- |
| 瓦片缓存，9 线程 | 0 / 600 | 5.11 ms | 3.02 ms | 8.34 ms | 200 / 200 |
| 整屏重绘，9 线程 | 0 / 600 | 5.31 ms | 1.89 ms | 8.24 ms | 200 / 200 |
| 瓦片缓存，单线程 | 0 / 600 | 6.78 ms | 2.13 ms | 7.38 ms | 200 / 200 |
| 整屏重绘，单线程 | 0 / 600 | 9.90 ms | 0.97 ms | 11.39 ms | 200 / 200 |

“Slint 绘制”是 Slint 接过一张 2560×1440 的新图片、上传成纹理并画出来的耗时。

## 结论

在这台机器上，CPU 渲染路径在 60 Hz 下通过，GPU 路径不是必需的。

这个结论的适用范围有限：

- 测试机是高端机型。预算要在选定的基准机型上重测后才能冻结。
- 内置屏是 60 Hz。在 120 Hz 屏上每帧只有 8.3 ms，上表里“处理加绘制”的 7 到 11 ms 已经没有余量。
- 3840×2160 只测了无窗口部分，没有测 Slint 接收 33 MB 图片的耗时。
- 内容只有文字，没有图片、表格边框和形状。
- 只测了 macOS。

## 实测中发现的问题

- **Slint 的渲染回调在 macOS 上不触发**。`set_rendering_notifier` 返回成功，但 Skia 渲染器的 Metal 表面没有实现对应接口，回调永远不会被调用。任务书里设想的“用渲染回调在 Slint 场景下层或上层自绘”在这个组合上走不通。
- **macOS 上 Slint 不靠 winit 的重绘事件出帧**。它用显示链接直接驱动绘制，`RedrawRequested` 只在启动时出现一次。想知道一帧何时画完，只能像 `window.rs` 那样用一个每帧求值的属性绑定来打点。
- **瓦片缓存与整屏重绘不是逐位相同**。720×600 的一帧里有 3 到 7 个抗锯齿像素相差 1 级，原因是两者的坐标原点不同，字形位置在 f32 下舍入不同。肉眼不可见，但黄金图对比必须允许 1 级误差，或者固定使用同一种策略。
- **按键延迟不能定义成“按键到帧提交不超过 16 ms”**。帧要等下一次屏幕刷新才能上屏，在 60 Hz 屏上这个数天然接近 16.7 ms。有意义的指标是“处理加绘制的耗时小于一个刷新周期”和“每次按键都在下一次刷新上屏”。
- **从后台启动的窗口不会被绘制**。测量必须让窗口在前台。
